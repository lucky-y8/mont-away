# 山遥积分礼品与履约规则

## 当前实现

- 管理员维护礼品标识、中/英/日名称和说明、兑换积分、库存与上下架状态。
- 用户看到的礼品名称和说明随 `Accept-Language` 返回，兑换记录保留当次积分总额。
- 兑换时在同一数据库事务中锁定用户与礼品，检查余额和库存，再扣减积分与库存。
- 积分账本以兑换 ID 和流水类型建立唯一约束，避免同一兑换重复扣款或退款。
- 用户或管理员只能在 `pending_fulfillment`（待发货）状态取消；取消会在同一事务中返还积分和库存。
- 管理员录入物流单号后状态变为 `shipped`（已发货），并向用户发送可本地化通知；发货后不能在系统内直接取消。
- `cancelled`（已取消）是终态。兑换记录不物理删除，便于审计。

## 当前采用的可调整假设

真实礼品及奖励积分数尚未由用户确认，因此代码不预置礼品，也不写死奖励额度。当前先采用“单一库存、人工发货、发货前可退、发货后不可退”的安全最小规则；这些是本轮实现假设，不表示最终运营政策已经确认。

## 上线前仍需确认

1. 发帖审核通过的奖励积分数、每日/每月上限和反作弊规则。
2. 真实礼品清单、图片、库存来源、每人限兑次数和配送范围。
3. 发货后退换货、丢件和违规帖子已兑换礼品时的处理方式。
4. 是否连接物流 API；当前仅保存管理员录入的物流单号。
5. 收件信息保存期限、加密、脱敏和删除策略。
