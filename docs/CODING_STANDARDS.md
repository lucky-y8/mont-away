# 山遥代码与多语言约定

## 注释

- 对业务状态、权限、安全边界、第三方适配器和不直观算法使用中英文双语注释。
- 格式优先采用 `English. / 中文。`，避免逐行翻译显而易见的语法。
- 公共模块和关键函数使用双语 docstring；变量与稳定接口字段统一使用英文，便于跨语言协作。

## API 文案与数据

- 客户端通过 `Accept-Language` 传递界面语言，服务端通过 `Content-Language` 声明实际返回语言。
- 错误结构固定为 `{ "error": { "code": "stable_code", "message": "localized text" } }`。客户端逻辑只依赖 `code`，`message` 只用于展示。
- 用户创作的标题、正文和地点原名按原文保存，并记录 `content_language`；翻译内容未来放独立缓存，不覆盖原文。
- 通知持久化 `event_type + payload`，读取时本地化，避免数据库只保存固定中文。
- 当前 API 支持简体中文、英文和日文；未知语言回退简体中文。

## 数据库与状态

- 正式环境只通过 Alembic 迁移升级，不使用 `create_all` 代替版本迁移。
- 帖子的公开、审核、奖励状态分别建模。发布立即公开，审核通过后奖励到账；奖励流水有唯一约束以避免重复发放。
- 媒体上传先归属当前用户，发布或保存草稿时再绑定内容版本；编辑时复制媒体元数据，旧版本不会丢失素材引用。
